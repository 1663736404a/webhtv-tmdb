## 四、P0：正确性与资源安全

### ✅ P0-01 保留 HLS Master Playlist 的完整多码率 Variant

- 交付：取消 `MpvHlsProxy` 无条件删除较低 Variant；所有 Variant 和关联 URI 均正确代理；分别保存 `BANDWIDTH` 峰值与 `AVERAGE-BANDWIDTH` 平均值语义。
- 直接收益：恢复 MPV/IJK 既有 HLS 码率选择的真实作用，为后续自动选轨保留可选择空间。
- 风险预览：MPV 与 IJK 的原生选轨行为不同；部分异常 Master Playlist、备用音轨和字幕组可能暴露新的兼容边界。
- 验收重点：最高/限 15Mbps/限 8Mbps/最低设置可区分；含音频组、字幕组、相对 URI、CRLF 和缺失属性的清单不被破坏。
- 依赖：无。后续：`M-05`、`I-01`。
- 实施结果：代理不再删除任何普通、I-frame 或图片 Variant；所有关联 URI 继续经本地代理改写，`BANDWIDTH` 与 `AVERAGE-BANDWIDTH` 分开记录，并在播放器实际请求子清单时输出不含 URL 的 Variant 诊断。
- 验证：新增 6 个清单重写单测；`androidx.media3.mpvplayer` 共 33 个单测通过；Mobile/Leanback arm64 Debug Java 编译通过。因当前没有真实 HLS 服务端，本项未把“真机实际选择最高/限码率档”误标为已验证，后续由 `M-05`、`I-01` 补齐端到端选轨验收。
- 提交：本项提交；标签：`playback-optimization-item-99`。

### ✅ P0-02 修正 EXO 带宽上限字段并回读实际轨道

- 交付：让 `capByBandwidth()` 修改 TrackSelector 真正使用的 `maxVideoBitrate`；记录约束值与实际选中 `Format`，验证是否发生越界。
- 直接收益：消除“日志显示已降码率、实际约束未生效”的确定性错误。
- 风险预览：现有用户可能首次真正触发降清晰度；`setExceedVideoConstraintsIfNecessary(true)` 仍可能在无匹配轨时越过约束。
- 验收重点：纯策略单测覆盖字段变化、最低边界和无可选轨；运行日志区分“请求上限”和“实际轨道”。
- 依赖：无。后续：`E-04`。
- 实施结果：带宽降级现在将估算带宽的 80% 写入 TrackSelector 实际读取的 `maxVideoBitrate`，保留 profile 名义码率，并继续使用 1Mbps 下限、15 秒冷却和原有触发条件。实际视频轨切换时记录请求上限、分辨率、帧率、Media3 约束码率及其峰值/平均值来源，并明确标记未知、约束内或越界；保留 `setExceedVideoConstraintsIfNecessary(true)` 的原有无匹配轨兜底。
- 验证：新增 6 个带宽上限策略用例，补充 Media3 峰值优先、平均值回退的诊断用例；EXO 包共 27 个测试类、122 个单测通过；Mobile arm64 单测变体与 Leanback arm64 Debug Java 编译通过。当前没有真实多码率服务端，因此本项仍未把真机端到端降档及无匹配轨越界兜底标记为已验证。
- 提交：本项提交；标签：`playback-optimization-item-100`。

### ✅ P0-03 恢复保守的首次带宽先验

- 交付：移除由设备理论解码能力推导的 20～40Mbps 起始估计；首次选轨采用 Media3 内置先验或经证据校准的保守先验。
- 直接收益：降低首个真实吞吐样本出现前误选高码率、起播慢或首次重缓冲的概率。
- 风险预览：高速 LAN/优质网络首次选轨可能更保守，短时间画质较低且需要等待 ABR 升档。
- 验收重点：各网络类型起始值不再由“设备可解码码率”抬高；已有可信样本后仍能正常升档。
- 依赖：无。后续：`E-05`。
- 实施结果：删除了由解码 profile 推导 8～40Mbps 起始带宽的 `InitialBitrateSupplier`，启用带宽估算时直接使用锁定 Media3 版本按国家和网络类型提供的内置先验：Wi-Fi/以太网约 0.86～4.3Mbps、4G 约 0.68～2.5Mbps、5G NSA 约 0.98～4.7Mbps、5G SA 约 1.0～2.7Mbps，未知网络为 1Mbps。保留项目现有 `4000` 滑动窗口权重、P0-02 码率上限修正及原有降档触发/冷却逻辑。
- 验证：新增 2 个带宽计配置回归用例，覆盖未知、Wi-Fi、以太网、2G、3G、4G、5G NSA、5G SA、离线及其他网络，确认初值来自 Media3 内置集合而非设备 profile；EXO 包共 28 个测试类、124 个单测通过；Mobile/Leanback arm64 Debug Java 编译通过。当前没有真实多码率服务端，因此高速 LAN 首次选轨画质、真实样本形成后的 ABR 升档速度仍待端到端验证。
- 提交：本项提交；标签：`playback-optimization-item-101`。

### ⬜ P0-04 禁止 IJK 自动场景绕过有限队列

- 交付：自动/稳定直播默认 `infbuf=0`，所有场景都受 `max-buffer-size` 控制；把判定提取为可测试策略。
- 直接收益：消除长时直播无限读包导致 native 内存持续增长和进程被杀的高优先级风险。
- 风险预览：RTSP/RTMP/UDP 等抖动链路可能更早停读或丢包，现有缓存水位需要后续重新校准。
- 验收重点：自动、推荐、直播稳定及各 realtime 协议均不启用无限缓存；自定义行为边界明确。
- 依赖：无。后续：`I-02`、`I-03`。

### ⬜ P0-05 建立共享磁盘缓存容量与保留空间算法

- 交付：提供纯策略模型，以“当前可用空间减必须保留空间”为新增缓存上限，区分缓存已用、可新增、用户限额和安全下限。
- 直接收益：让 EXO 与 MPV 使用同一安全语义，避免把卷总容量比例误当成仍可写空间。
- 风险预览：保留值过大时缓存命中率下降，过小时仍可能挤满磁盘；不同卷和异常文件系统返回值需防溢出。
- 验收重点：接近满盘、缓存已存在、极小/极大卷、负数/溢出和目录不可用均有纯单测。
- 依赖：无。后续：`P0-06`、`P0-07`。

### ⬜ P0-06 EXO 磁盘缓存接入保留空间并处理写满

- 交付：`MediaSourceFactory` 使用 `P0-05` 容量策略；空间不足或 ENOSPC 时停止新增/预载、清理可回收项并保持前台播放可恢复。
- 直接收益：降低 SimpleCache 侵占保留空间和磁盘写满造成播放失败的概率。
- 风险预览：SimpleCache 容量在活动会话中不能随意重建；错误处理过度可能导致缓存反复释放。
- 验收重点：容量延迟切换状态机、活动会话、空间骤降和写失败路径均被覆盖。
- 依赖：`P0-05`。

### ⬜ P0-07 MPV HLS 代理磁盘缓存接入保留空间并处理写满

- 交付：代理缓存使用 `P0-05` 容量策略；写入失败时停止预取、清理安全对象，并允许请求退化为直通。
- 直接收益：避免固定 512MiB 等限额在小容量或接近满盘设备上造成 ENOSPC。
- 风险预览：边播边删存在并发竞态；直通回退会增加网络请求且可能暴露上游不支持 Range 的问题。
- 验收重点：并发读写、活跃对象保护、清理顺序、写失败和直通回退测试。
- 依赖：`P0-05`。

### ⬜ P0-08 修正 VBR/REMUX 媒体码率估计

- 交付：`Format.bitrate` 不再无条件屏蔽可信内容平均值和观测 p90；输出平均需求、突发需求、来源与置信度。
- 直接收益：减少 VBR 峰值被低估后缓存预算不足、网络保护误判或预载错误开启。
- 风险预览：异常高样本可能抬高需求；错误扩容会增加内存，因此低置信度样本只能抑制升级，不能直接扩容。
- 验收重点：CBR、VBR、错误 Format、完整文件平均值、p50/p90、孤立异常和饱和运算。
- 依赖：无。后续：`E-01`、`E-05`。

### ⬜ P0-09 将字节位置斜率限制到单连续 Progressive 流

- 交付：只在确认单数据流、连续 Range/位置单调时使用 byte slope；HLS/DASH 多 DataSource、Seek、重开和并发加载立即失效。
- 直接收益：避免分片并发递增 sequence 导致错误码率、错误缓存和错误升档决策。
- 风险预览：部分网盘代理无法可靠分类时会失去一项估计来源，需要退回 Format/长度/时长信息。
- 验收重点：Progressive 连续流保留估计能力；HLS/DASH、Seek、重连、并发音视频均不产生伪可信 slope。
- 依赖：`F-02` 或先使用最小路径分类器；后续：`E-05`。

## 五、F：共享事实层

### ⬜ F-01 建立 `PlaybackAutoContext` 不可变事实模型

- 交付：定义设备、资源、路径、运行反馈、值来源、置信度、采样时间和过期规则；初始只采集和记录，不改变播放行为。
- 收益：三个内核共享同一组事实和术语，决策可解释、可复现。
- 风险预览：对象更新过频会增加主线程和日志负担；字段边界不清会形成新的全局状态。
- 依赖：P0 可独立先做；后续所有自动控制项依赖。

### ⬜ F-02 实现协议、资源与播放路径分类

- 交付：区分本地/LAN/远程/内部服务/外部 loopback，Progressive/HLS/DASH/RTSP/RTMP，以及 VOD/live/LL-live、Range、segment/part 和 hold-back。
- 收益：避免仅凭 URL scheme 决定缓存、直播或吞吐可信度。
- 风险预览：代理 URL 会隐藏原协议；错误分类会把直播当点播或误信 loopback 本地腿。
- 依赖：`F-01`。

### ⬜ F-03 接入内存事实与压力事件分发

- 交付：接入 Java heap、`MemoryInfo`、`getMyMemoryState()`、`onTrimMemory/onLowMemory` 和低成本 native 指标；API 34+ 不依赖废止的 running trim 回调。
- 收益：自动缓存和预载首次拥有真实系统压力闭环。
- 风险预览：生命周期、线程和多 Activity 分发错误可能产生泄漏或错杀前台任务；PSS 只能用于稀疏诊断。
- 依赖：`F-01`。

### ⬜ F-04 接入网络成本、热状态与电源事实

- 交付：采集 validated、metered、roaming、Data Saver、Battery Saver 和 thermal status，并监听会话期变化。
- 收益：自动档可在计费、发热或省电状态下抑制升档与预载。
- 风险预览：旧 Android API、权限缺失和厂商错误上报必须以 unknown 处理，不能误判为安全。
- 依赖：`F-01`。

### ⬜ F-05 接入真实轨道、显示与 decoder 事实

- 交付：记录实际 MIME/profile/level、分辨率、帧率、HDR、平均/峰值码率、实际 decoder、输出模式/tunneling 和显示模式。
- 收益：以实际播放事实替代固定 HEVC/最大显示模式预检。
- 风险预览：轨道切换和 decoder 重建期间快照短暂不一致，需要序列号和有效期。
- 依赖：`F-01`。

### ⬜ F-06 统一自动决策日志和核心遥测

- 交付：记录每次决策的输入、置信度、旧值、目标值、原因、抑制原因，以及首帧、buffer、吞吐、重缓冲、掉帧、内存、live lag 等核心指标。
- 收益：能定位自动档为何做出某个选择，并为 A/B 校准提供证据。
- 风险预览：日志量、性能和 URL/请求头隐私；默认必须脱敏、限频且不记录密钥。
- 依赖：`F-01`～`F-05`。

## 六、E：EXO 自动控制器

### ⬜ E-01 按媒体需求和真实内存计算 EXO target bytes

- 交付：目标取“平均/突发媒体需求、约 200MB guard、设备会话预算”三者最小值，并按 16/24/48/64/96/128/192MiB 保守层级调整。
- 收益：避免固定 256MiB 一刀切，同时为高码率单轨提供与需求匹配的缓存。
- 风险预览：Media3 target bytes 是软目标，时间优先时仍可能突破；预算过小会增加高码率重缓冲。
- 依赖：`P0-08`、`F-03`、`F-05`。

### ⬜ E-02 分离本地、流媒体、多码率和高码率单轨 LoadControl

- 交付：多码率默认字节优先；高码率单轨仅在硬保护有效时受控时间优先；本地和网络使用不同起播/重缓冲边界。
- 收益：避免全局 `prioritizeTime` 或全局字节优先在相反场景中产生退化。
- 风险预览：资源类型误判会改变加载停止条件；Media3 新版本 guard 行为需持续复核。
- 依赖：`E-01`、`F-02`。

### ⬜ E-03 实现内存压力下的 EXO 快速降级与迟滞恢复

- 交付：压力时先停预载、back=0、禁扩张并降低缓存层；恢复需稳定窗口和冷却期。
- 收益：前台播放优先，降低 OOM 和系统杀进程风险。
- 风险预览：频繁压力事件可能导致参数抖动；allocator 已分配内存不一定立即归还。
- 依赖：`F-03`、`E-01`。

### ⬜ E-04 重构自定义限制层与 Media3 ABR 的职责

- 交付：HLS/DASH 由 Media3 ABR 实时选轨；项目层只施加设备、显示、codec、热、计费和故障上限；Progressive 不再执行虚假“降 variant”。
- 收益：消除双重 ABR、只降不升和震荡职责冲突。
- 风险预览：移除旧控制器后，某些重缓冲场景的主动降档时机可能变化。
- 依赖：`P0-02`、`F-02`、`F-04`、`F-05`。

### ⬜ E-05 建立短/长窗口吞吐和路径可信度模型

- 交付：短窗口负责快速降级，长窗口负责谨慎升级；排除 loopback 本地腿和并发预载污染，记录预测误差。
- 收益：弱网恶化时响应更快，恢复时减少画质震荡。
- 风险预览：窗口和阈值需要真机 trace 校准；样本不足时必须保守而非猜测。
- 依赖：`P0-03`、`P0-08`、`P0-09`、`F-02`、`F-06`。

### ⬜ E-06 自动计算起播、重缓冲和 buffer 趋势阈值

- 交付：按协议、segment/part、网络波动、time-to-empty 和历史重缓冲动态设定阈值，升级慢、降级快。
- 收益：稳定资源更快起播，波动资源减少反复卡顿。
- 风险预览：阈值变化过于频繁会造成 LoadControl 行为难以预测。
- 依赖：`E-02`、`E-05`。

### ⬜ E-07 隔离并过期 EXO 重缓冲学习

- 交付：学习键包含网络、路径、协议和资源类型；异常记录有过期和版本失效机制。
- 收益：避免某次坏链路永久拖慢所有资源起播。
- 风险预览：维度过细会导致样本稀疏，过粗则继续交叉污染。
- 依赖：`F-02`、`E-06`。

### ⬜ E-08 完善前台优先的自动预载控制

- 交付：结合吞吐比、buffer 趋势、计费、漫游、省电、热和内存控制 0～2 线程；风险事件立即取消。
- 收益：网络充裕时改善下一集起播，拥塞或压力时不抢当前播放。
- 风险预览：取消不彻底仍可能占连接；2 线程可能触发网盘限流或代理竞争。
- 依赖：`F-03`、`F-04`、`E-05`。

### ⬜ E-09 建立 decoder 运行能力档案和版本化黑名单

- 交付：按 fingerprint、App/Media3、decoder、格式、规格、secure、输出模式记录成功、掉帧、错误和回退；版本变化后可重新验证。
- 收益：解决静态 API 报支持但运行失败的厂商兼容问题。
- 风险预览：错误持久化会不必要降画质；设备升级后陈旧黑名单必须失效。
- 依赖：`F-05`、`F-06`。

### ⬜ E-10 实现 EXO RTSP live lag 恢复

- 交付：检测落后直播边缘和异常增长，按能力跳最新位置或重建会话，并设置冷却和重试上限。
- 收益：避免 RTSP 卡顿后持续播放历史内容并积累内存。
- 风险预览：live edge 不可靠时跳转会丢内容；频繁重建可能造成连接风暴。
- 依赖：`F-02`、`F-06`。

## 七、M：MPV 自动控制器

### ⬜ M-01 让 MPV“自动”进入独立自动控制器

- 交付：不再把 `applyAuto()` 等同 `applyRecommended()`；先建立保守初始配置和状态机骨架，不擅自覆盖用户 `mpv.conf`、字幕、LUT、滤镜和速度。
- 收益：MPV 自动档从固定推荐值转为可反馈控制。
- 风险预览：配置优先级处理错误会覆盖用户明确设置；必须保留自定义和原版回退。
- 依赖：`F-01`、`F-02`。

### ⬜ M-02 按事实运行时扩缩 MPV forward cache

- 交付：从 24/48/64/96MiB 保守层起步，按需求和余量扩至 128/192MiB；压力时立即缩容并记录真实 total/forward/RSS 趋势。
- 收益：降低当前固定 256MiB 在普通设备上的 native 内存压力，同时保留高码率扩张能力。
- 风险预览：修改上限不会保证 RSS 立即回落；过小初始值可能增加首次停顿。
- 依赖：`M-01`、`F-03`、`P0-08`。

### ⬜ M-03 按向后 Seek 行为自动管理 MPV back cache

- 交付：默认 0；满足真实回看行为和内存余量后逐步启用 16/32/64MiB，直播、无 Seek 或压力时归零。
- 收益：不为多数不会回看的会话固定占用约 128MiB。
- 风险预览：首次向后 Seek 可能重新请求网络；forward 可借用 back，统计必须按潜在总量计算。
- 依赖：`M-02`、`F-06`。

### ⬜ M-04 消除 MPV 缓存时间参数重复语义

- 交付：明确 `cache-secs` 与 `demuxer-readahead-secs` 的单一主控关系，并以小规模实验评估 hysteresis。
- 收益：减少配置互相覆盖，让日志展示值与实际行为一致，并可能降低持续唤醒功耗。
- 风险预览：hysteresis 过大可能放大网络突发；不同 demuxer 对时间目标响应不一致。
- 依赖：`M-02`。

### ⬜ M-05 实现 MPV HLS 初始 Variant 与受控降档重载

- 交付：使用可信吞吐选择初始 `hls-bitrate`；持续 underrun 时以有冷却、保进度的重载/重启方式降档。
- 收益：避免固定最高档在弱网永久缓冲，并补足 MPV 无无缝 ABR 的现实限制。
- 风险预览：重载会产生短暂中断、鉴权或时间点偏移；直播和 VOD 必须分开处理。
- 依赖：`P0-01`、`F-02`、`E-05` 可复用的吞吐事实。

### ⬜ M-06 将内存、热、电源和网络成本接入 MPV 自动降级

- 交付：压力时停预载、back=0、缩 forward、禁升级；恢复使用迟滞窗口。
- 收益：native cache 不再脱离系统状态固定扩张。
- 风险预览：MPV 属性更新线程和生命周期错误可能造成死锁或对已释放实例写属性。
- 依赖：`M-02`、`M-03`、`F-03`、`F-04`。

### ⬜ M-07 实现 MPV 前台优先预载与代理预算联动

- 交付：按真实上游吞吐、播放 buffer 和代理缓存预算控制 0～1 线程；外部 loopback 默认关闭。
- 收益：避免预载、HLS 代理和当前播放争抢同一上游链路或磁盘。
- 风险预览：无法识别上游遥测时只能保守关闭，可能牺牲下一集起播速度。
- 依赖：`P0-07`、`F-02`、`F-04`、`M-06`。

## 八、I：IJK 自动控制器

### ⬜ I-01 用清单和时间线识别 IJK VOD/live/LL-live

- 交付：不再只看 URL scheme；解析 HLS `ENDLIST`、target/part duration、hold-back，并为无法判断场景保留 unknown。
- 收益：普通 HTTP HLS 直播可获得正确的低延迟和有限缓存策略。
- 风险预览：代理改写或不规范清单可能缺失标签；unknown 必须采用安全回退。
- 依赖：`P0-01`、`F-02`。

### ⬜ I-02 按设备和场景控制 4/8/15MiB 有限队列与水位

- 交付：在 `infbuf=0` 前提下，按 target/part duration、live lag、内存和重缓冲反馈设置有限队列。
- 收益：在可控内存内平衡直播延迟与抗抖动能力。
- 风险预览：IJK 固定 native 版本对某些 option 的实时更新能力有限，可能需要安全重建。
- 依赖：`P0-04`、`F-03`、`I-01`。

### ⬜ I-03 实现 IJK RTSP/RTMP 延迟超限恢复

- 交付：检测 lag 和队列增长，按协议丢旧、跳最新或重建会话，而非只增加 buffer。
- 收益：长时直播卡顿后可回到实时位置，且内存不持续累积。
- 风险预览：丢帧或重建会造成可见跳跃；协议端不支持定位时只能重连。
- 依赖：`I-02`、`F-06`。

### ⬜ I-04 按实际解码压力控制 picture queue 与软解降负载

- 交付：picture queue 默认 3，仅依据真实软解、掉帧和 thermal 调整；必要时降低轨道或切换已验证回退路径。
- 收益：避免高分辨率时盲目把队列增到 5/8 进一步消耗 native/图形内存。
- 风险预览：队列过小可能增加渲染抖动；轨道能力取决于 HLS 是否存在可选 Variant。
- 依赖：`F-04`、`F-05`、`I-01`。

### ⬜ I-05 建立 IJK 运行反馈与内核回退记录

- 交付：统一记录重缓冲、掉帧、native 增长、decoder error 和回退结果，形成可过期的设备/格式档案。
- 收益：IJK 自动档从固定参数升级为能从失败中恢复和学习的控制器。
- 风险预览：IJK 回调粒度较粗，不能把缺失数据误判为运行良好。
- 依赖：`F-06`、`I-02`、`I-04`。

## 九、V：联合验收与档位收敛

### ⬜ V-01 建立自动参数实验开关与快速回滚

- 交付：高风险策略具有本地开关、默认安全值、版本化迁移和一键回退到上一稳定策略的能力。
- 收益：问题设备无需等待大版本即可停止实验行为。
- 风险预览：开关过多会增加组合复杂度，必须有统一默认和过期清理规则。
- 依赖：至少一个自动控制器进入实验阶段。

### ⬜ V-02 完成自动化场景与策略测试矩阵

- 交付：覆盖 low-RAM、普通 TV、4K/HDR、HLS/DASH、Progressive/REMUX、loopback/VPN、直播、RTSP、软解、Seek、近满盘和 codec 虚报。
- 收益：防止单一测试资源掩盖另一类设备或协议退化。
- 风险预览：JVM 单测无法替代 native 播放、网络 trace 和真机长稳测试。
- 依赖：随各阶段持续补充，最终在收敛档位前完成。

### ⬜ V-03 完成 EXO 帧提前调度真机 A/B 基础设施

- 交付：只对命中实验设备测试 50/75/100ms early scheduling 与 duration-to-progress，采集帧提前/延后、掉帧和首帧，不修改全局常量。
- 收益：可能改善特定电视的帧调度，同时避免经验值污染全部设备。
- 风险预览：需要可重复的 Perfetto/真机样本；错误归因可能掩盖 decoder 或显示模式问题。
- 依赖：`F-05`、`F-06`、`V-01`。

### ⬜ V-04 收紧 VOD 网络保护降速的产品边界

- 交付：自动档默认不改变用户播放速度；多码率优先 ABR；单码率救援仅在用户显式允许时短时、可撤销启用。
- 收益：避免把 Media3 直播速度区间误用为 VOD 最佳实践，也避免无提示延长片长。
- 风险预览：极端单码率弱网将失去现有自动降速兜底，可能更早暴露资源不可持续。
- 依赖：`E-04`、`E-05`、`V-01`。

### ⬜ V-05 自动档与推荐/均衡档完成分组 A/B 验收后合并

- 交付：按设备、decoder、协议比较 P50/P95 首帧、重缓冲、峰值内存、掉帧和 live lag；达标后将推荐/均衡入口合并到自动，并保留迁移。
- 收益：实现“多个档位是完善自动档的过渡阶段”的产品目标。
- 风险预览：总体均值可能掩盖小众设备退化；任何关键分组未达标都不能合并。
- 依赖：`E`、`M`、`I` 核心项与 `V-02` 完成。

### ⬜ V-06 分别评估轻量档和兼容档的最终去留

- 交付：先判断自动档是否覆盖 low-RAM/软解场景，再决定轻量档；兼容档仅在厂商 codec、输出和协议异常都有可靠自动回退后最后评估。
- 收益：减少用户难以理解的固定档位，同时不提前移除关键逃生通道。
- 风险预览：移除过早会让问题设备失去稳定回退；此项必须拆成两次独立产品决策，不能默认删除。
- 依赖：`V-05` 及问题设备长期数据。
